# 지식 반영·승격

대화·리뷰·지적에서 나온 내용을 **Git 파일에 남겨** 다음 작업에서 AI가 다시 읽게 한다.
모델이 “기억”하는 것이 아니라, 이 저장소의 파일이 학습 데이터다.

이 파일은 **절차만** 둔다. 사실·규칙 본문은 아래 표의 파일에 둔다.

## 지적 반영 (같은 턴)

사용자·리뷰 지적은 **별도 학습 기록을 만들지 않는다.** 같은 턴에 아래를 모두 수행한다.

1. 지적 내용을 고친다.
2. 규칙화 기준(아래)으로 규칙인지 1회성인지 판단한다.
3. 규칙이면 아래 표의 해당 파일에 반영한다.
4. 기계로 잡을 수 있으면 `scripts/harness/banned.txt` 또는 `scripts/harness/check.sh` 에 추가한다. 글 규칙은 다시 무시될 수 있고, 기계 점검은 hook·CI 가 막는다.

| 내용 | 적을 곳 |
|------|---------|
| 특정 앱 스택·DB·설정·도메인 | `.ai/projects/{앱}.md` |
| 모듈 빌드·test 명령, 모듈 convention (`build.gradle` 주석 등) | `{모듈}/AGENTS.md` |
| 스택 공통 코딩 (Java, React, API 등) | `.ai/rules/{해당}.md` |
| 입구·읽기 순서·레이아웃·문서 동기화·bootstrap | 루트 `AGENTS.md` |
| 사람용 결과 | `README.md`, `docs/` (근거 아님) |

- **규칙화 기준:** 다음 작업에도 적용될 기준이면 규칙으로 남긴다. 특정 문장 표현 같은 1회성 수정은 해당 파일만 고친다.
- 한 사실은 **한 파일에만 본문**으로 둔다. 다른 파일은 포인터만.
- 이 파일에 앱 사실·규칙 본문을 넣지 않는다.
- 한 줄이라도 같은 턴에 남긴다. “나중에”만 남기지 않는다.

## 공통으로 승격 (사람 승인)

`.ai/projects/` 또는 한 앱 전용 내용이 **다른 앱·스택에도 통한다**고 확신될 때만 `.ai/rules/common.md` 등 **공통 rules** 로 올린다.

- AI는 승격 **후보와 근거만 제안**한다. 승격·문구 확정은 **사람이** 한다.
- 이름이 비슷하거나 한 앱에서만 맞는 내용은 공통으로 올리지 않는다.
- 승격 시 앱 전용 표현·경로는 분리한다.

## 검증

루트 `AGENTS.md` 「하네스·일관성 검증」을 따른다.

## 하지 않는 것

- 대화만 하고 파일에 남기지 않기
- 이 파일을 학습 로그·사실 모음으로 쓰기
- 같은 사실을 여러 파일에 본문으로 적기
- 확인 없이 rules 전체에 장문 복붙
- `docs/` 내용을 구현 근거로 쓰기
- 검증 한 줄 보고 없이 “완료”라고 말하기

## Cursor 전용 (선택, 나중)

`.cursor/rules/*.mdc` glob 으로 경로별 자동 첨부는 **Cursor 보조**다. Claude·Copilot 은 `AGENTS.md` + 이 파일 + 위 표를 따른다.
