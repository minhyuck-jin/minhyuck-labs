# HTTP API 규칙

백엔드·프론트가 같은 HTTP API를 쓸 때 적용한다.
공통 응답 래퍼 여부는 아직 정하지 않았다. 첫 API를 만들 때 물어본다.

## URI
- 소문자, 하이픈(`-`). 밑줄·캐멀케이스·대문자를 쓰지 않는다
- 자원은 명사. 집합은 복수형 (`/orders`, `/order-items`)
- 슬래시(`/`)는 자원 계층에만 쓴다. URI 끝에 `/` 를 붙이지 않는다
- 조회·생성 같은 동사를 경로에 넣지 않는다 (`/getOrder` 금지)
- 계층을 과하게 중첩하지 않는다. 필터·검색 조건은 쿼리스트링으로 둔다
- 경로에 API 버전을 넣지 않는다 (`/v1/orders` 금지). 헤더·쿼리로도 버전을 기본 두지 않는다

## HTTP 메서드
- 조회: GET
- 생성: POST
- 전체 수정: PUT
- 부분 수정: PATCH
- 삭제: DELETE
- 조회를 POST 로 두지 않는다. (복합 검색이 필요하면 그때 경로를 물어본다)

## 상태 코드
- 성공은 2xx, 클라이언트 오류는 4xx, 서버 오류는 5xx
- HTTP 200 응답 바디에 오류 코드를 넣어 실패를 표현하지 않는다

## 오류 응답
- 오류 응답 형식을 API 전체에서 통일한다
- 스택 트레이스, 내부 클래스명, 쿼리 같은 내부 구현을 응답으로 내보내지 않는다
