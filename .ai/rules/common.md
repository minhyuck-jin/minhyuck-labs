# 공통 기술 규칙

모든 스택에 적용한다.

## 파일
- 소스와 텍스트는 UTF-8
- 개행은 LF. CRLF가 섞이지 않게 한다 (`.gitattributes`, `.editorconfig`)
- 파일 끝은 개행으로 끝낸다

## 이름
- 식별자는 영문, 숫자, 언더스코어만 쓴다
- 한글 발음을 영어로 옮긴 이름은 쓰지 않는다
- 이름이 의미를 드러내게 한다. 한 글자 이름은 짧은 범위의 임시 변수만 허용한다

## 작업 방식
- 요청한 범위만 수정한다. 추측으로 구현하거나 범위를 넓히지 않는다
- 수정 전에 관련 기존 코드를 읽는다. 없는 API·설정·테이블을 있는 것처럼 쓰지 않는다
- 확신이 없으면 추측하지 말고 선택지를 물어본다
- 헬퍼·공통 유틸·추상 계층은 기본으로 만들지 않는다. 필요하면 장단점을 말하고 동의를 받는다
- 변경 후 해당 모듈의 테스트, 빌드, 린트가 있으면 실행한다. 없으면 실행 방법만 적는다

## 문서
- 구현·분석의 근거는 코드와 `.ai` 이다
- `README.md` 와 `docs/` 는 근거로 쓰지 않는다. 구조·공개 프로젝트·하네스가 바뀌면 같은 작업에서 최신화한다

### `.ai` 규칙 층 (섞지 않음)
| 위치 | 넣을 내용 |
|------|-----------|
| `.ai/rules/` | 스택·언어 **공통** (예: Flyway 파일명, `#{}` 바인딩). **특정 앱·모듈 경로, JPA/MyBatis 선택, DB 종류** 는 넣지 않는다 |
| `.ai/projects/{앱}.md` | 그 **앱**의 DB·프레임워크·경로·도메인 |
| `{모듈}/AGENTS.md` | 그 **Gradle 모듈**의 빌드·test·모듈 전용 convention (예: `build.gradle` 주석) |
