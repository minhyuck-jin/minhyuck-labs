# 테스트 규칙

테스트 코드에 적용한다. 러너·라이브러리 **메이저 버전을 이 파일에 고정하지 않는다.**
앱을 만들 때 해당 스택에서 쓰기 좋은 최신을 고른다. (예: Java면 그때의 현행 JUnit, React면 그때의 현행 Vitest 또는 Jest)

## 이름
- 테스트 클래스·파일 이름은 `Test` 로 끝낸다 (`OrderServiceTest`, `OrderList.test.tsx`)
- 테스트 식별자는 영문. 한글 설명은 `@DisplayName`, 테스트 제목 문자열 등에 둔다

## 작성
- 순서는 given(준비) → when(실행) → then(검증)
- 한 테스트는 한 가지 행동만 검증한다

## 범위
- 단위 테스트는 실제 DB·네트워크 없이 작성하는 것을 기본으로 한다. 의존은 mock 또는 테스트 더블
- 통합 테스트(실제 DB, 서버 기동)가 필요하면 동의를 받는다

## 러너
- 한 모듈에서 테스트 러너나 메이저 버전을 섞지 않는다
- 새 모듈의 기본 선택은 “지금 그 스택에서 쓰기 좋은 최신”이다
